## 三、代码修改清单

### 1. `test\e2e\investments.spec.ts`

**1a. `ensureAccount` 余额放大**（定期用例前置）
- 新建 savings 账户余额 `1000` → `10000000`（1 亿元），确保定期本金 5000 + 费用 可覆盖

**1b. 定期用例扣款账户显式指定工资卡**
- 原：`fillIfVisible(page, "扣款账户", "", "select", 2)`（索引不稳定）
- 改：先选第 1 个真实账户保底（新建 savings 自身，同账户跳过守卫），再通过 `selectOption` 显式选择「工资卡」（种子期初余额 100 万元），并读回校验、失败重试一次，杜绝受控 select 偶发未同步

**1c. 复制持仓用例清理段修复**（连带暴露的既有缺陷）
- 原：`tr.filter({ hasText: name })` 删除时，子串匹配同时命中原行与「（副本）」行，strict mode violation；正则锚定方案又因 hasText 对整行文本匹配而失效
- 改：先删副本行（仅副本行含「（副本）」子串唯一），再删原行；每轮删除后等待 `toHaveCount(0)` 确认行消失，避免 DOM 未刷新导致下一轮误匹配

### 2. `test\e2e\manage-recurring.spec.ts`

**2a. 新增周期计划显式选择工资卡**
- 原：未选账户，默认 `accounts[0]`（现金，余额 -2000）
- 改：表单中显式 `selectOption` 选择「工资卡」（余额充足），保证「执行本期」通过余额守卫并生成流水

**CSV 中文表头解析错误（import-export 失败根因）**
