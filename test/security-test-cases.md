# ratcount · 安全测试案例（Security Test Cases）

> 版本：v1.1 ｜ 范围：认证/会话、越权、注入、XSS、CSRF、敏感信息、审计 ｜ 执行方式：手动 + 工具

## 一、概述

安全测试验证系统内置安全基线：参数化查询、bcrypt 密码、验证码防重放、登录限流、`ledger_id` 强制隔离、角色权限、CSRF/XSS 防护、审计留痕（**仅 C/U/D 写操作**，含请求/响应内容，按用户维度隔离）。**高风险项（S1）必须全过才能交付。**

## 二、用例明细

### S1 认证与会话

| 用例ID | 目标 | 操作 | 预期结果 | 优先级 |
|---|---|---|---|---|
| SEC-S1-01 | 未登录访问 | 直接访问 /dashboard、/accounts 等 | 302 重定向 /login | P0 |
| SEC-S1-02 | 会话有效性 | 篡改/伪造会话 cookie | 无法伪造，被拒绝 | P0 |
| SEC-S1-03 | Cookie 属性 | 检查 `AUTH_SECRET` 签发 cookie | HttpOnly + Secure(生产) + SameSite | P0 |
| SEC-S1-04 | 密码存储 | 查库 `users.password_hash` | bcrypt 加盐哈希（非明文/非 MD5） | P0 |
| SEC-S1-05 | 验证码一次性 | 用同一 token 登录两次 | 第二次失败（防重放） | P0 |
| SEC-S1-05b | 验证码纯函数 | `verifyCaptchaToken` | ✅ 自动化：正确/小写/篡改/伪造 4 条（`unit.test.ts`） | P0 |
| SEC-S1-06 | 验证码过期 | 等待 >5 分钟后登录 | 验证码失效，需刷新 | P1 |
| SEC-S1-07 | 登录限流 | 同 IP 连续 5 次失败 | 第 6 次被拒 15 分钟 | P0 |
| SEC-S1-08 | 首用户提权 | 多用户注册 | 仅首个注册为 admin | P1 |
